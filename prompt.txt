layer 2:

This module implements a **fully admin-controlled moderation system** where:

* Users can be reported (by admin or volunteers)
* Admin analyzes behavior
* Admin applies actions:

  * Restriction (partial block)
  * Suspension (full block)

All actions are:

* Time-based
* Logged in AdminLogs
* Communicated via messages + email

---

# 1. AdminLogs Model

```js
AdminLogs {
  id: ObjectId,

  action: String, 
  // REPORT_USER 
  // RESTRICT_USER 
  // SUSPEND_USER 

  user_id: ObjectId,

  metadata: {
    reason?: String,
    durationDays?: Number
  },

  timestamp: Date
}
```

---

# 2. User Model (Moderation Fields Required)

```js
reportCount: Number,
restrictionUntil: Date | null,
suspendedUntil: Date | null
```

---

# 3. Admin Reporting Flow (Admin → User)

---

## Trigger

Admin clicks **Report button** in Opportunity Details page

---

## Modal Input

* Reason (text input)
* Suggested reasons (click to autofill)
* Checkbox: Delete Opportunity
* Buttons:

  * Report User
  * Suspend User

---

# 4. Report User Action (Restriction Flow)

---

## Step 1: Optional Deletion

```js
if (checkboxChecked) {
  delete opportunity
}
```

---

## Step 2: Apply Restriction

```js
const duration = 1 * 24 * 60 * 60 * 1000;

user.restrictionUntil = Date.now() + duration;
await user.save();
```

---

## Step 3: Send Message (Admin → NGO)

* Navigate to messages page
* Open NGO chat

### Message Content:

```
Report

Hello ${user.name},
We observed improper behaviour in "${opportunity.title}".
This is a warning.

You are not allowed to create opportunities for 1 day.
```

---

## Step 4: Send Email

* Use existing email system
* Subject: "Report"
* Body same as message

---

## Step 5: Create Admin Log

```js
createAdminLog("RESTRICT_USER", user._id, {
  reason: reason,
  durationDays: 1
});
```

---

# 5. Suspend User Action (Admin → User)

---

## Input:

Admin selects duration:

```
3 days, 7 days, 15 days, 1 month, custom
```

---

## Step 1: Optional Deletion

```js
if (checkboxChecked) {
  delete opportunity
}
```

---

## Step 2: Apply Suspension

```js
const duration = days * 24 * 60 * 60 * 1000;

user.suspendedUntil = Date.now() + duration;
await user.save();
```

## Step 3: Send Message

```
Report
```

* Same content
* Subject: "Report"

---

## Step 5: Create Admin Log

# 8. AdminLogs Page Behavior

---

## Display:

* Action
* User ID
* Metadata (reason, duration)
* Timestamp

---

## Additional Feature: "Report User"

---

### Modal Fields:

* Search user by username
* Reason
* Action:

  * Restrict
  * Suspend
* Duration (for both)

---

## On Submit:

---

### Apply Action:

```js
if (action === "restrict") {
  user.restrictionUntil = Date.now() + duration;
}

if (action === "suspend") {
  user.suspendedUntil = Date.now() + duration;
}

await user.save();
```

---

### Send Message:

```
Admin Action

Hello ${user.name},
You have been ${action} for ${days}.

Reason: ${reason}
```

---

### Send Email:

* Same content

---

### Create Log:

```js
createAdminLog(action.toUpperCase(), user._id, {
  reason,
  durationDays: days
});
```

---

# 9. Enforcement Logic (Critical)

---

## Restriction (Partial Block)

### NGO:

* Cannot create opportunities
* Cannot claim pickups

### Volunteer:

* Cannot apply opportunities
* Cannot schedule pickups

---

## Suspension (Full Block)

* Cannot login
* Cannot access any route

---

## Middleware

```js
const now = Date.now();

if (user.suspendedUntil && now < user.suspendedUntil) {
  block login + routes
}

if (user.restrictionUntil && now < user.restrictionUntil) {
  req.isRestricted = true
}
```

---

# 10. Auto Expiry

---

```js
if (user.restrictionUntil && now > user.restrictionUntil) {
  user.restrictionUntil = null;
}

if (user.suspendedUntil && now > user.suspendedUntil) {
  user.suspendedUntil = null;
}
```

---

# 11. Important Rules

1. Reports DO NOT auto-trigger actions
2. Only admin applies restriction/suspension
3. Restriction = partial block
4. Suspension = full block
5. Suspension overrides restriction
6. All actions must be logged
7. Messages + Emails must always be sent
8. Do NOT create extra tables for reports

---
